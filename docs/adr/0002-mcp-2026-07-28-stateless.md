# 0002. MCP protocol 2026-07-28 and stateless mode

- Status: Accepted
- Date: 2026-11-19
- Note: Recorded retroactively: moved from the *Design decisions* section of `ARCHITECTURE.md`.

## Context

The 2026-07-28 revision of the MCP spec removes sessions (`Mcp-Session-Id`) and the
`initialize` handshake: each request carries its protocol version, the client's
capabilities and identity in `_meta`.

## Decision

- **Downstream**, the gateway serves every request without a session, including for older
  clients (`legacy_session_mode(false)`).
- **Upstream**, one rmcp client shared per server. Upstreams still on a 2025-xx version keep
  their sessions, managed by rmcp (an expired session is reopened automatically).
- `tools/list` returns `ttlMs` and `cacheScope: public`: the list is the same for every
  client.

## Alternatives considered

- Keep MCP sessions: they require sticky sessions in front of the replicas, and a pod
  restart disconnects clients.

## Consequences

- Any pod can serve any request: several replicas work without sticky sessions, and a pod
  restart disconnects no client.
- No per-client state may be introduced in the gateway.
- Enables configuration changes through rolling updates (ADR-0003).
